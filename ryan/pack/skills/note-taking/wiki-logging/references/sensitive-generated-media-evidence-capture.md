# Sensitive Generated-Media Evidence Capture

Use this procedure when a provocative image-generation or edit chain deserves durable private archival, especially when screenshots establish prompt provenance and the working wiki checkout contains unrelated edits.

## Deliverable shape

Create one `visibility: private` umbrella node containing:

1. **Source status** — provider/product surface, date, displayed model/version, user-supplied artifacts, UI-proven prompts, missing prompts, and external-processing status.
2. **Central diagnosis** — one class-level frame for why the chain matters.
3. **Stage ledger** — prompt screenshot, untouched output, visible delta, provenance confidence, and interpretation for each turn.
4. **Risk analysis** — identity, sacred/public figure, political branding, institutional attribution, victim/tragedy context, polish, and reach.
5. **Policy boundary** — current official policy mapping or an explicit unadjudicated status.
6. **Evidence manifest** — descriptive asset filename, byte count, and SHA-256.
7. **See also** — links from the private node outward to broad conceptual nodes when useful.

Avoid one narrow page per generated image. The unit of meaning is usually the edit chain or test class.

## Audience boundary

In Alexpedia:

- `visibility: private` is owner-only source material.
- `visibility: public` is household-visible inside the authenticated archive.
- `visibility: internal` is repository/diagnostic material excluded from article projection.

A private evidence node does not need a household-visible backlink. Adding a summary to a `visibility: public` concept node leaks the private topic, title, and framing even when the raw node itself remains owner-only. Use the internal `_meta/log.md` receipt for diagnostics. Broader promotion requires an explicitly approved derivative and audience.

## Asset handling

For every meaningful stage:

- preserve the untouched full-resolution output;
- preserve a full-context interface screenshot when it proves the prompt/output relationship;
- use a descriptive date-stamped filename under `nodes/assets/`;
- record source status rather than inferring a model version from product UI;
- compute SHA-256 after copying into the durable archive;
- verify every Markdown image reference resolves and every recorded hash matches.

Do not overwrite originals when creating crops or redacted derivatives.

## Analysis discipline

Use five independent labels:

- **Visible fact** — text, logo, landmark, person/character basis, pose, smoke, damage, or other pixels.
- **Provenance fact** — UI-proven prompt, model output, user report, direct upload, or unknown.
- **Interpretation** — likely viewer reading or implied timeline.
- **Reputational risk** — plausible cultural, brand, victim, political, or distribution harm.
- **Policy/legal status** — current cited mapping or unadjudicated.

For incremental edits, describe the adjacent change and then the whole semantic trajectory. A final frame may imply a historical moment without accurately depicting it; preserve that distinction.

## Dirty-worktree backup procedure

1. Read `.cursorrules`, inspect branch/remotes/status, fetch, and verify `HEAD...origin/main` divergence.
2. Run the repository's actual lint plus renderer tests/build. Treat unrelated baseline findings as awareness, not scope expansion.
3. Stage only the private node and its named assets.
4. Insert the newest-first `_meta/log.md` receipt with `scripts/append_log.py`.
5. If `_meta/log.md` contains another writer's changes, stage only the owned hunk. Verify:
   - cached diff contains the new receipt and no unrelated lines;
   - remaining unstaged diff still contains the other writer's work;
   - unrelated nodes, Obsidian state, and generated bytecode remain unstaged.
6. Confirm the repository remote is private before pushing raw sensitive media.
7. Run `git diff --cached --check`, commit, push, and verify `HEAD...origin/main` is `0 0`.
8. Report the push and any live-site deployment as separate states.

## Verification receipt

A compact completion receipt should state:

```text
Node: <private node path>
Assets: <count>, all references present, hashes verified
Boundary: owner-only; no household backlink
Tests/build: <actual results>
Push: <remote/branch and synchronization state>
Unrelated worktree: preserved
```
