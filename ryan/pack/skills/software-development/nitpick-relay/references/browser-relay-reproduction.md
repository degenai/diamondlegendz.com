# Browser relay reproductions

- Freeze and hash the source outside the live repository; record pre-existing dirty paths and verify their hashes at closure. Compare deployed JS/CSS/ICS bytes independently of HTML, since edge-injected analytics and email obfuscation can legitimately change HTML.
- Treat browser launch flags as part of the experiment. Playwright Chromium disables back-forward cache by default; remove only `--disable-back-forward-cache` for a BFCache-specific probe and require a real `pageshow.persisted === true` restoration before accepting or rejecting a back-navigation finding.
- Intercept every non-read-only HTTP method in isolated form tests. Fulfill declared response fixtures in the browser and distinguish this from real backend acceptance or email delivery. Use disposable browser contexts and synthetic guest data.
- Capture native GET submissions as well as POST when testing missing/failed JavaScript: forms without method/action put field values in the document URL. Arm a navigation interceptor after initial load and fulfill the resulting navigation locally so even synthetic submissions never reach the host. Bind endpoint mocks to the actual source constant instead of a guessed URL.
- Wait for finite reveal animations to settle before judging opacity or visibility. A fixed screenshot delay can sample a correctly running spring/stagger timeline and create a false missing-content finding. Check computed motion behavior as well as module guards, because older CSS particle loops can remain active under reduced motion.
- Label selected-source manifests separately from complete tracked-file inventories. A missing path in a deliberately filtered review packet cannot prove repository absence or publication safety. Adjudicate routing with actual status/body controls: a static HTML redirect stub or published PDF can preserve a route even when a host-specific redirect config is inert.
- Compare commercial prices only for the same venue, duration and eligibility; a regular charge and a free introductory offer are distinct contracts. Require downstream observation for availability/checkout claims, and keep a public landing-page 200 separate from a successful reservation.
- Trace reviewer-proposed exclusions and clone-depth changes to their consumers before adopting cleanup advice. A served helper may be required by a page, and full git history may feed an active changelog updater even when an older generation step is dead.
- Model stalled response bodies separately from stalled headers. A fetch Promise resolves on headers; subsequent JSON parsing can remain pending. A browser-native Response/ReadableStream fixture should honor the actual AbortSignal, and any accelerated watchdog should retain the production timeout identity. Pair the reproduction with a minimal in-memory positive control; never call a fake endpoint response a live result.
- Verify SRI hypotheses with a harmless altered-module canary under the real page's integrity declaration, then a control that removes only integrity in memory. Seeing both preload and import in source does not establish a bypass.
- Compare disputed HTTP statuses against a known-public positive control using the same User-Agent. A blanket 403 affecting both excluded files and the homepage is a transport/filtering observation, not proof of publication rules or authentication.
- Record raw findings and adjudications separately. Deduplicate symmetric paths, calibrate severity to implemented state rather than invented guest IDs, and preserve intentional recovery/persistence behavior unless actual harm is shown. A reviewer consensus or a clean-check sentence is weaker than a reproduced counterexample.
- Reduce streaming reviewer output before displaying it: preserve the complete stream on disk, validate the terminal result, and print only its model/session receipt plus normalized verdict. Token-by-token text events are not useful parent context.
- Recover completed review artifacts after an interrupted tool delivery before rerunning the model. Match pass ID, successful wrapper status, schema validity and input/source hashes; retain the interruption receipt separately.
